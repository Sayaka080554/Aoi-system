# 蓄水池 · 互购净额台账 演示（demo）

对应讨论：互购净额台账（2026-10-14 六项口径已拍板；正式实现待立项 `docs/PLAN-RESERVOIR.md`，随 v3.25.0）

**这是什么**：和日本/韩国代购互买谷子的「挂账本」——订单计入蓄水池两侧（A=TA 帮我买/我欠，B=我帮 TA 买/TA 欠），
实时按币种看净额，攒到合适时机一次结清，替代「每笔都转账」的不便与手续费。
纯静态交互演示（HTML/CSS/原生 JS，零依赖、零构建、离线可开），数据全部是写死的 mock，改动存浏览器 localStorage。

## 演示口径（已拍板）

1. **一池多对手方**：转账通常由一人完成，订单来自多人多活动，池内按购买人小计。
2. **手工账同步新建订单**：记一笔手工账会同步新建一笔「手工」标记的真实订单（备注「蓄水池手工账」），可在订单库排查。
3. **按订单自身汇率分币种统计**：每币种外币合计 + 对应人民币合计两套口径；未转化的人民币/外币该笔留空并橙色提醒。
4. **结算流水**：转账/换货抵账记一笔，净额即时冲抵（方向=对方→我方冲抵TA欠 / 我方→对方冲抵我欠）。
5. **金额自动跟随订单改价**：池内条目引用订单，改价后合计与净额即时反映。
6. **仅管理员可见**，团员端不暴露；导出对账单放二期。
7. **结算即标记**：展开明细勾选订单 →「结算勾选订单（标记已结算）」，确定后这些订单标记「已结算」——
   移出活水净额、订单库勾选框禁用（之后无需再勾选）；删除该条结算流水自动取消标记、金额回到活水。
   纯转账（不勾订单，用「记一笔结算」）照旧只冲抵净额，不标订单。

## 演示路径（建议顺序）

1. 看「日本线 · 佐桑结算」卡头净额：日元 我方欠对方 6,400（= 侧A 11,400 − PayPal 结算 5,000）、人民币 对方欠我方 ¥49
2. 点「展开明细」：币种汇总表 / 按购买人小计（佐藤·田中两人在同一池）/ 侧A·侧B 明细 / 结算流水
3. 注意两处橙色提醒：田中的亚克力「未转¥」、手工挂件「未转外币」——这两笔在合计里留空
4. 切「订单库」：勾选一两个未入池订单 → 选池与侧向 → 「计入蓄水池」；已在池中的订单自动跳过
5. 「改价（演示跟随）」改一笔在池订单的价格 → 回池子看合计/净额已自动跟随
6. 「记一笔手工账」→ 填外币金额自动按演示汇率折人民币 → 确定后订单库出现「手工」标记新订单
7. 「记一笔结算」→ 看净额即时扣减；流水表可删；展开明细后还可勾选订单点「结算勾选订单（标记已结算）」——
   弹窗按勾选预填方向/金额，确定后该行变灰「已结算」、订单库勾选框禁用，删除该流水自动取消标记
8. 「＋ 新建蓄水池」试建第三个池；「重置演示数据」一键还原

## 数据说明

- 种子 mock：2 池 / 10 笔订单（含 2 笔未转化、1 笔手工）/ 1 笔结算；存 localStorage 键 `rsd_demo_v1`，
  控制台 `localStorage.removeItem('rsd_demo_v1')` 或点「重置演示数据」还原。
- 演示汇率 jpy 0.048 / krw 0.0053 仅用于手工账的人民币折算建议值；正式版金额一律读订单自身已转化字段
  （`priceOrig`/`currency`/`price`），不设全局汇率。
- 冒烟与净额计算测试：`tests/reservoir-demo.test.js`（jsdom，demo 独立加载，不占主 harness）。
