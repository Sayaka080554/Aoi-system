# REPORT-FORMALIZATION — 正式化部署调研报告（域名 / 双小程序 / 扫码支付 / 日韩面向 / QQ bot）

> 调研日期：2026-10-20 · 状态：调研结论，待批准后按 §八 顺序实施
> 范围：专属域名 + 正式网站 + 微信/QQ 小程序 + 直接扫码支付（做 / 不做两案）+ 面向海外（日韩）代购 + QQ 机器人维持
> 前提事实：47.101.194.103（阿里云 SWAS 轻量应用服务器）确认始终正常运行（负责人 2026-10-20）；F12 C 端商城 V1 已实装（收款码转账 + 尾数人工确认）；登录链路 = 邮箱 OTP；收款/订单已并入管理端同一 blob。

---

## 一、结论速览（TL;DR）

1. **小程序只需做一份**——2025 年起 QQ 已可直接运行微信小程序（2025-05 QQ 9.1.70 小范围测试，2025-07 起迁移通道打通，旧版 QQ 小程序体系被微信小程序框架逐步取代）。做微信小程序 + 走 QQ 互通/迁移通道即可覆盖「qq+微信小程序」两个诉求，无需单独开发与认证 QQ 小程序（实施时以 q.qq.com 当期指引为准）。
2. **「做不做扫码支付」的分界线在资质，不在代码**：
   - **不接微信支付**：小程序端不能出现任何交易（平台明令禁止诱导规避微信支付、禁止个人收款码收经营款），只能做查单/进度/通知；收款留在自有 H5 网站（收款码模式，合规边缘见 F3）。
   - **接微信支付**：需个体工商户执照（免费自办）→ 微信小程序企业主体认证（¥300/次，年审 ¥300/年）→ 微信支付商户号（免费开通、标准费率 0.6%、个体户可用经营者个人银行卡结算）。H5 用 Native 扫码支付，小程序内用 JSAPI 支付。
3. **服务器零新增**——47 SWAS 复用为备案载体 + nginx 静态站 + QQ bot（NapCat/relay/Caddy），仅需确认套餐剩余时长 ≥3 个月（申请备案服务名额的要求）。
4. **年度新增固定成本 ≈ ¥400–500**（域名 ¥60–100 + 小程序认证 ¥300），支付通道本身免费、按交易额收 0.6%。
5. **日韩面向**：货源端在日韩不产生任何境内平台资质；备案域名对日韩用户照常可访问；跨境收款（服务日韩本地客户收当地货币）需海外主体 + 当地金融牌照，一期不做（见 §六）。

## 二、关键调研发现（2026-10 时点）

- **F1 · 微信小程序已打通 QQ**：QQ 侧旧版小程序体系弱化，官方引导迁移到微信小程序框架；对本项目意味着单份开发覆盖两端，QQ 小程序单独认证/备案成本归零。
- **F2 · 小程序支付红线**：微信《小程序运营规范》明确禁止诱导用户规避微信支付；微信支付官方规则规定二维码收款仅限纯个人收款，商户收款将被关停。小程序任何页面（含 web-view 加载的 H5）展示个人收款码/引导转账均属违规。
- **F3 · H5 收款码模式的合规边缘**：央行新规（2022-03 起）个人静态收款码不得用于远程非面对面经营性收款。F12 V1 的「收款码 + 尾数确认」属此边缘场景——实践中小规模普遍如此，风险形态是个人码被风控限额/停用，而非法律责任；正式化后建议切商户收款码（即路线 B）彻底消除。
- **F4 · 微信小程序认证**：企业主体认证 ¥300/次（第三方审核机构收，失败不退），**每年年审另付 ¥300**；公众号认证资质不可复用到小程序（同一法人也不行）；未认证小程序不能接微信支付。
- **F5 · 微信支付商户号**：个体工商户可申请，结算账户可用经营者个人（对私）银行卡；标准费率 0.6%（不可自行调整，实体优惠行业 0.38%–0.5%，服务商渠道可谈更低）；Native 支付即「PC 网站商城下单、用户扫码」的标准形态；开通审核约 1–2 工作日。
- **F6 · 小程序备案强制**：备案五环节 = 备案信息填写 → 平台初审 → 工信部短信核验 → 通管局审核 → 备案成功；未完成备案的小程序无法上线运营（2023-09 起新规，2026 年仍执行）。
- **F7 · 跨境收款门槛高**：微信支付境外机构商户需合法海外主体 + 当地国家/地区金融服务或资金处理类牌照 + 独立网站/APP；直连模式目前仅香港、英国开放。个体户/个人主体不可行——一期不做跨境收款。

## 五、两条路线对比（直接扫码支付：不做 vs 做）

### 路线 A · 不接支付（小程序只做非交易功能）
- H5 网站：保留 F12 V1 收款码 + 尾数人工确认模式（风险见 F3）。
- 小程序：查单 / 我的订单 / 进度通知 / 到货通知——纯查询展示，无交易、无收款码、不接支付。
- 资质：Q1–Q5（个体户仍建议办理，规避个人备案站点展示交易内容的整改风险）。
- 固定年成本：≈ ¥400–500。
- 优点：零交易费率、上线最快；缺点：收款合规边缘、依赖人工对账、后续补接支付需要变更小程序类目。

### 路线 B · 全链路微信支付（推荐终态）
- H5：Native 扫码支付（PC 商城标准形态，用户扫码即付）。
- 小程序：JSAPI 支付，交易在微信内闭环。
- 资质：Q1–Q7 全套。
- 固定年成本：≈ ¥400–500 + 交易额 × 0.6%。
- 优点：合规、支付回调自动核销（可替代尾数人工确认环节）；缺点：执照先行、类目审核、有费率。

**分期建议**：路线 A 先上线 → 执照办妥后切路线 B。F12 代码侧已预留支付位（PLAN-F12 §9.4），切换主要发生在资质与商户配置层，不阻塞首版上线。

### 小程序内不可逾越的红线（两路线通用）
不得在小程序任何页面（含 web-view 加载的 H5）展示个人收款码或引导转账——违反运营规范，轻则下架、重则封主体。因此路线 A 的小程序必须与交易页面严格隔离；路线 B 使用微信支付/商户码则无此问题。

## 六、海外（日韩）面向说明

- **货源端（现状模型：国内成员买日韩谷子）**：不产生任何境内平台资质；进货付款方式（PayPal / Wise / 国际汇款 / 当地代购渠道）属业务侧选择，与平台合规无关。
- **访问端**：备案域名解析大陆服务器，日韩用户照常访问（延迟略高；Supabase 后端在海外节点，对国内与日韩两侧对称）；无备案之外的额外义务。
- **客户端在日韩（远期选项，一期不做）**：若未来要向日本/韩国本地消费者直接收款（收日元/韩元），需跨境收单——微信支付跨境商户要求海外主体 + 当地金融牌照（直连仅香港/英国开放），个体户不可行；Stripe 不对大陆主体开放，Airwallex 类同样需企业资质。过渡方案可评估「日韩用户外卡内绑微信支付」。
- 若未来以日本实体/常驻形态在日经营，需遵守日本《特定商取引法》的展示义务——仅作远期备注，当前个人代购小规模不涉及。

## 七、QQ bot 维持方案（零新增资质）

- NapCat（QQ 协议端，建议小号规避非官方协议风险）→ 落 47 SWAS（已确认正常运行，且公网可达，relay 可直连回调）。
- relay 维持双通道现状互备：SWAS relay v4.1 + Supabase Edge qq-relay v7/v8。
- Caddy TLS 按 F5 部署清单执行；NapCat 上报地址指向 relay。
- 与小程序无耦合：QQ 内运行的微信小程序与 bot 是两条独立链路，互不影响。
- 沿用 F5 剩余待办：NapCat 上报配置 / Caddy TLS / schema 重跑（RPC 已在库则跳过）/ SSH 部署者公钥授权（47 与 106 两机）。

## 八、实施顺序建议

1. **第 0 周**：买域名并实名；确认 47 SWAS 套餐剩余时长 ≥3 个月；启动个体户执照办理（线上申请，1–2 周）。
2. **第 1 周**：执照到手后以个体户主体提交 ICP 备案（**建议等执照再备案**——备案主体后续变更流程繁琐；备案本身要 1–3 周，并行不延期）。
3. **备案等待期**：SWAS 部署 nginx + NapCat/relay/Caddy（bot 先行点亮）；GitHub Actions 增加部署步骤；小程序代码侧开发（路线 A = 原生查询页或 web-view 只读壳；路线 B = JSAPI 支付接入）。
4. **备案通过**：域名解析 SWAS → HTTPS 上下 → 静态站切换，旧 Pages 保留开发预览。
5. **微信小程序**：企业主体注册 → 认证（¥300）→ 小程序备案（平台内 1–2 周）→ 提审上架。
6. **路线 B 补充**：微信支付商户号开通 → Native/JSAPI 接入 → F12 收款码模式切商户码，支付回调自动核销。
7. **QQ 互通**：按 q.qq.com 当期官方指引将微信小程序迁入/映射 QQ 端。
8. **验收**：日韩访问延迟实测、bot 全链路回归、支付回调对账、备案号页脚检查。

## 九、风险清单与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| H5 收款码模式处央行个人静态码远程收款新规边缘（F3） | 中 | 一期内可运行；切路线 B 商户码彻底消除 |
| 小程序内出现收款码 → 下架/封主体 | 高 | 路线 A 严格隔离交易页面；交付检查项中加「小程序内无收款引导」 |
| 个人备案站点展示交易内容被管局要求整改 | 中 | 用个体户主体备案 |
| 纯 web-view 壳小程序审核收紧 | 中 | web-view 内功能与 H5 完整一致、无支付引导；备选原生重写核心查询页 |
| NapCat 非官方协议封号 | 低-中 | 小号运行 + Edge/SWAS relay 双通道降级 |
| 微信↔QQ 互通迁移通道政策变化 | 低 | 互通为加分项不阻塞主链路，随时可退回纯 H5 |
| Supabase 海外存储与 PIPL | 低 | 站点挂隐私政策/用户协议页，数据最小化 |
